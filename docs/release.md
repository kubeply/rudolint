# Release Automation

`rudolint` release artifacts are built by `cargo-dist` from GitHub Actions. Do
not cut releases from a local machine.

## Tooling

- `dist-workspace.toml` pins `cargo-dist` to `0.32.0`.
- `rust-toolchain.toml` pins the Rust toolchain used by release builds until
  `1.0.0`.
- `.github/workflows/release.yml` is generated by `dist generate`.

Regenerate release workflow files after changing `dist-workspace.toml`:

```bash
dist generate
dist plan --output-format=json
```

## Targets

The release workflow builds archives for:

- `x86_64-unknown-linux-gnu`
- `aarch64-unknown-linux-gnu`
- `x86_64-unknown-linux-musl`
- `aarch64-unknown-linux-musl`
- `x86_64-apple-darwin`
- `aarch64-apple-darwin`

Windows targets are intentionally excluded until Windows path handling and shell
behavior have dedicated CI coverage.

## Artifacts

Tag pushes that look like semantic versions publish a GitHub Release with:

- one archive per target
- `.sha256` sidecar files
- aggregate `sha256.sum`
- source tarball
- shell installer
- GitHub artifact attestations

Pull requests run `dist plan` only. They verify release metadata without
building or publishing release artifacts.
