# DL3059 consecutive-run

- Default severity: info
- Category: compatibility
- Provenance: Hadolint-compatible Dockerfile rule.
- Autofix: no safe automatic fix is declared because joining shell commands can
  change failure handling and cache behavior.

Suggests combining adjacent `RUN` instructions with the same flags when neither
instruction already contains more than two shell commands.

This rule is intentionally `info` severity because adjacent `RUN` instructions
are often a build-size or cache-shape tradeoff, not a correctness issue. Large
project Dockerfiles may split setup phases into many small `RUN` instructions to
keep review diffs clear, isolate cache invalidation, or document platform setup
steps. In those cases the finding is useful as performance guidance, but it is
reasonable to suppress or downgrade it for files where readability is the
preferred tradeoff.

Rudolint keeps the rule conservative by only reporting directly adjacent `RUN`
instructions with matching flags and small shell bodies. It does not suggest an
autofix because joining shell commands can change failure handling, cache
behavior, and the line that receives future diagnostics.

Bad:

```Dockerfile
RUN apk add --no-cache curl
RUN rm -rf /tmp/*
```

Good:

```Dockerfile
RUN apk add --no-cache curl && rm -rf /tmp/*
```

Configure with `.rudolint.yaml` `ignore` or `severity` entries when needed.

Example project-level suppression when consecutive `RUN` instructions are an
intentional style:

```yaml
ignore:
  - DL3059
```

Example profile-oriented workflow when this should stay advisory:

```console
rudolint check . --profile performance --failure-threshold warning
```
