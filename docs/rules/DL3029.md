# DL3029 no-from-platform-flag

- Default severity: warning
- Category: compatibility
- Provenance: Hadolint-compatible Dockerfile rule.
- Autofix: no safe automatic fix is declared because platform selection is a build policy decision.

Avoids hard-coding `--platform` on `FROM` instructions. Prefer selecting the
platform at build time.

In the default, correctness, performance, and hardening profiles, rudolint
allows `--platform` values that use Dockerfile variables because they keep the
platform selectable at build time. This covers Docker BuildKit's automatic
`$BUILDPLATFORM` and `$TARGETPLATFORM` arguments as well as project-specific
`ARG` values. The `hadolint-compat` profile keeps Hadolint-style behavior and
still reports every `FROM --platform` use.

Bad:

```Dockerfile
FROM --platform=linux/amd64 alpine:3.20
```

Good:

```Dockerfile
FROM alpine:3.20
```

Also accepted outside `hadolint-compat`:

```Dockerfile
FROM --platform=$BUILDPLATFORM golang:1.22 AS build
FROM --platform=linux/${TARGETARCH} alpine:3.20 AS target
```

Configure with `.rudolint.yaml` `ignore` or `severity` entries when needed.
