# RDK1010 frontend-version-supports-syntax

- Default severity: warning
- Category: buildkit
- Provenance: Rudolint BuildKit-native rule.
- Autofix: no safe automatic fix is declared because changing the Dockerfile frontend can change builder behavior.

Detects Dockerfiles that pin `# syntax=docker/dockerfile:<version>` to a
frontend version older than the syntax used later in the file. Floating tags
such as `docker/dockerfile:1` are treated as acceptable because Docker
documents them as the latest stable version for the v1 syntax line.

This rule checks Dockerfile frontend minimum versions for `RUN` options and
`ADD`/`COPY` options documented in the Dockerfile reference, plus
here-documents.

Bad:

```Dockerfile
# syntax=docker/dockerfile:1.3
FROM alpine:3.20
RUN --security=sandbox true
COPY --link src/ /dst/
COPY --chmod=+x src/tool /usr/local/bin/tool
```

Good:

```Dockerfile
# syntax=docker/dockerfile:1
FROM alpine:3.20
RUN --security=sandbox true
COPY --link src/ /dst/
```

Good with a pinned frontend:

```Dockerfile
# syntax=docker/dockerfile:1.20
FROM alpine:3.20
RUN --security=sandbox true
COPY --parents src/file /dst/
COPY --chmod=+x src/tool /usr/local/bin/tool
```

Good with a labs frontend:

```Dockerfile
# syntax=docker/dockerfile:1.7-labs
FROM alpine:3.20
COPY --parents src/file /dst/
```

Reference:

- Dockerfile reference: `RUN` option minimum versions, `ADD` and `COPY` option
  minimum versions, and parser directive behavior:
  <https://docs.docker.com/reference/dockerfile/>

Configure with `.rudolint.yaml` `ignore` or `severity` entries when needed:

```yaml

  RDK1010: error

# or suppress the rule entirely:

  - RDK1010
```
