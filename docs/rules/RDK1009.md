# RDK1009 multi-platform-host-architecture

- Default severity: warning
- Category: buildkit
- Provenance: Rudolint BuildKit-native rule.
- Autofix: no safe automatic fix is declared because architecture mapping depends on the downloaded artifact or build toolchain.

Detects multi-platform Dockerfiles that appear to use the build host
architecture instead of the target architecture. The rule looks for Buildx
multi-platform intent, then reports host architecture probes such as
`uname -m`, `arch`, `dpkg --print-architecture`, and `apk --print-arch` when a
`RUN` step does not reference target platform variables. It also reports a final
stage pinned to `$BUILDPLATFORM`, because that would publish an image for the
builder host rather than the requested target platform.

Bad:

```Dockerfile
FROM --platform=$BUILDPLATFORM alpine:3.20 AS build
ARG TARGETARCH
RUN curl -fsSL "https://example.invalid/tool-$(uname -m).tar.gz" -o /tmp/tool.tar.gz

FROM --platform=$BUILDPLATFORM scratch
```

Good:

```Dockerfile
FROM --platform=$BUILDPLATFORM alpine:3.20 AS build
ARG TARGETARCH
RUN curl -fsSL "https://example.invalid/tool-${TARGETARCH}.tar.gz" -o /tmp/tool.tar.gz

FROM --platform=$TARGETPLATFORM scratch
```

Configure with `.rudolint.yaml` `ignore` or `severity` entries when needed:

```yaml
severity:
  RDK1009: error

# or suppress the rule entirely:
ignore:
  - RDK1009
```
